# 06: Minimal-diff editor and write protocol

**What to build:** An agent can edit items safely: field, section and AC edit tools that patch the file in place as a minimal diff, under hash-verified, temp-and-rename writes with a per-file queue. Spec reference: `.scratch/tasklogmd/spec.md`, sections 3 (numbering and edits), 4 (write protocol), 5 (generic edit tools) and 12 (concurrency). Tools: `set_fields`, `replace_section`, `append_to_section`, `add_ac`, `edit_ac`, `toggle_ac`, `remove_ac`. Includes the test hook that pauses a write between hash verification and rename.

**Blocked by:** 05 Parser, scan and read tools

**Status:** ready-for-agent

- [x] Given a one-field edit, when written, then the file diff is exactly one line, byte-exact, with CRLF, key order, comments, quoting, blank lines and unknown sections preserved.
- [x] Given a stale hash, when a content edit is sent, then it fails `stale_hash` and the file is unchanged.
- [x] Given two writers racing one file, when both write, then exactly one succeeds and the other gets `stale_hash`.
- [x] Given an external edit between a client's read and write, when the client writes, then it is detected as stale.
- [x] Given interleaved edits to different ACs of one ticket, when queued, then both apply in order through the per-file queue.
- [x] Given a failure mid-write, when it occurs, then the original file is whole and no temp file remains; leftover temp files are swept at daemon start.
- [x] Given a hand-added AC without a number, when the next write occurs, then it gets the next free number; given an invalid or conflicted item, writes are refused.
- [x] `set_fields` cannot set `status` except `reopen: true`; tags are normalized to lowercase `[a-z0-9-]`.
- [x] Given the seeded randomized run, when N parallel clients apply random operations to a small workspace, then the file on disk always parses and equals a rescan.
- [x] Every write returns the new `hash` and registers the parse result in the store.

## Comments

Implementation notes for later tickets (07 watcher, 08 creation, 09 workflow tools, 11 observability).

**New modules.**
- `src/model/edit.ts`: pure `applyEdit(parse: ValidParse, edit: Edit, ctx: {id, effort}) -> {text, n?}`. `Edit` is a union on `op`: `set_fields | replace_section | append_to_section | add_ac | edit_ac | toggle_ac | remove_ac`. It patches the parser's offsets in place (key order, comments, quote style, list style, CRLF/LF per nearby line, blank lines, unknown sections kept). Returned `text` is BOM-less; the writer re-adds the BOM. Equal text means a no-op. Also exports `normalizeTag(s)` and `normalizeTags(list)` (lowercase, other chars to `-`, collapsed, deduped; ticket 08 should reuse them for `create_item`). Every edit is wrapped in AC renumbering (hand-added ACs without `#N` get max+1 in file order, before and after the edit) and a final "result must still parse" check that refuses the edit with `bad_request`.
- `src/daemon/writes.ts`: `WriteService(models, log)` (one per daemon, `RunningDaemon.writes`, `McpDeps.writes`). **The only API that writes item files**: `await writes.edit(root, id, hash, edit) -> {id, hash, changed, n?, path}`. `root` must be the canonical workspace root (the same string `resolveWorkspace` returns). Ticket 08/09 compose workflow tools from `edit()` calls (e.g. `resolve` = `replace_section` Answer, then `set_fields`-style status change). Status changes other than reopen are NOT available through `set_fields`; 09 needs an internal edit op for them (add an `Edit` variant, e.g. `set_status`, and expose it only through the workflow tools). The same goes for `claimed_by` and `updated`.
  - Protocol inside the per-file queue (key = absolute path): `idx.get(id)` (throws `not_found`/`conflicted`/`invalid_item`), read disk, hash vs the client's hash (`stale_hash`, and the model is caught up with the disk bytes as a side effect), parse the disk bytes, `applyEdit`, write `.<name>.<rand>.tasklog-tmp` beside the file (`wx`, fsync), test hook, re-read and re-check the disk hash (an external write during the pause gives `stale_hash`), rename (retries EPERM/EBUSY/EACCES a few times for Windows readers), then `idx.upsertFile(path, newBytes)` (registers the parse in the store, bumps the model version) and records the self-write. Any failure removes the temp file; the original is never touched before the rename.
  - **Test hook:** `daemon.writes.beforeRename = async (w: {root,id,path,op}) => {...}` (settable at any time; throwing simulates a mid-write failure).
  - **For the watcher (07):** `writes.isSelfWrite(root, relPath, hash)` is true when `hash` is the last content this service wrote to that path; drop the event if so. The model is already updated by the write, so no reparse is needed. `writes.idle()` resolves when all queues are empty.
  - `sweepTempFiles(root, log)` removes `*.tasklog-tmp` under `.tasklog/`; `ModelManager.ensure` calls it once, before a workspace's initial scan (not on rescans, since a rescan may overlap an in-flight write). `TEMP_SUFFIX` is exported; temp files are already ignored by `identify` because they do not end in `.md`.
  - A no-op edit (e.g. toggle to the current state, same tags) does not touch the file and returns the current hash with `changed: false`.
- `src/daemon/edit-tools.ts`: `registerEditTools(server, deps, ctx, wrap)`, called from `createMcpServer`. Tools: `set_fields {id, hash, title?, type? (null removes), tags?, blocked_by?, reopen?}`, `replace_section` and `append_to_section {id, hash, heading, content}`, `add_ac {id, hash, text, checked?}`, `edit_ac {id, hash, n, text}`, `toggle_ac {id, hash, n, checked?}`, `remove_ac {id, hash, n}`. All also take the optional `workspace`. All return `{id, hash, changed, path, n?}` (`changed` and `path` are additive to the spec's `hash, n`).

**Decisions.**
- Generic edits do **not** bump `updated` (the AC says a one-field edit is a one-line diff). Ticket 09 owns `updated` for claim/resolve/close/release, which is what stale-claim detection reads.
- `set_fields`: `status` (or any unknown status argument) is `bad_request` pointing at `reopen`. `reopen: true` sets `status: open` and removes `claimed_by`; on an already open item it fails `bad_transition`. `tags` replaces the list, normalised (a tag with no usable characters is `bad_request`). `blocked_by` replaces the list; digits-only strings become numbers, `thiseffort/NN` collapses to `NN`, `other/5` is padded to `other/05`, self-reference is `bad_request`. `type` only on tickets; `null` deletes the line. A new key is inserted after its canonical predecessor (`kind,title,status,type,claimed_by,blocked_by,tags,created,updated`). An existing key keeps its spacing, quote style, inline vs block list style and trailing comment.
- Sections: `heading` matched case-insensitively, a leading `#`s is ignored, first match wins. Content may not contain a `## ` line outside a code fence (`bad_request`). `replace_section` swaps only the non-blank body lines (the blank lines around it stay); empty content empties the section. `append_to_section` adds lines right after the last non-blank line; start the content with a blank line for a new paragraph. A missing section is created at the end of the file, except `Acceptance criteria`, which goes before `## Answer` when that exists.
- ACs: `add_ac` inserts after the last AC (or creates the section), number = max+1 over the section; `edit_ac` replaces only the text; `toggle_ac` flips one character (or sets `checked`); `remove_ac` deletes the line and renumbers nothing. A missing `#N` is `not_found`; duplicate numbers are `bad_request` (ambiguous). AC text must be one line and must not start with `#N`.
- Conflicted and invalid items are refused from the model's view (`conflicted`, `invalid_item`) before queueing, and again inside the queue. An item whose disk bytes no longer parse is `invalid_item` even if the model still had it valid.
- Gotcha for tests in this repo: the registry lower-cases roots on Windows, so call `d.models.ready(canonicalize(root))` and `writes.isSelfWrite(canonicalize(root), ...)`, not the raw fixture path.

**Tests.** `test/unit/edit.test.ts` (27 byte-exact edit cases: LF and CRLF, quoting, comments, block lists, section creation, AC numbering, refusals). `test/integration/write-tools.test.ts` (22: one-line diff and CRLF/BOM through the daemon, stale hash on every tool, external edit before and during the write, two racing writers, interleaved ACs, failure mid-write and failed rename leave no temp file, temp sweep at start, invalid/conflicted refusal, hand-added AC numbering, status/reopen/tags, and three seeded randomized runs with 6 clients x 25 steps asserting every file parses, no temp files, and a fresh `WorkspaceIndex` scan equals the live index hash for hash).

**Deviations/limits.** Block-list rewrites (tags or blocked_by written as a `- item` list) rewrite that whole key's lines and drop comments placed between its items. `edit_ac` on an AC whose line has trailing inline markup is a plain text replace. No watcher yet, so a stale model is repaired only when a write detects it. `Edit` has no `set_status`/`claimed_by`/`updated` variants; ticket 09 adds them.
